# Формат данных Winter Arc

Все данные лежат в **одном файле**: `public/data/data.json`
(после сборки он копируется в `dist/data/data.json`; сайт загружает его при каждом открытии,
поэтому для обновления данных **пересборка не нужна** — достаточно заменить JSON на хостинге).

> Сейчас в файле — РЕАЛЬНЫЕ данные (старт 01.10.2026, 30 дней до 30.10.2026). Примерные демо-данные лежат отдельно в
> `scripts/sample/sample-data.json` (`npm run gen-sample` пересоздаёт только их и реальный файл не трогает).

## Структура верхнего уровня

```jsonc
{
  "meta":      { ... },   // настройки арки
  "profile":   { ... },   // возраст, рост (справочно)
  "targets":   { ... },   // дневные/недельные цели (калории, часы и т.д.)
  "habits":    [ ... ],   // список отслеживаемых привычек
  "exercises": [ ... ],   // список упражнений для графиков и рекордов
  "goals":     { "month": [ ... ], "sixMonth": [ ... ] },
  "days":      { "YYYY-MM-DD": { ... } }   // ежедневные записи, ключ — дата
}
```

### meta
| поле | тип | описание |
|---|---|---|
| `title` | string | Заголовок («Winter Arc») |
| `sample` | bool | признак демо-данных (баннер убран; поле справочное) |
| `startDate` | `YYYY-MM-DD` | День 1 арки |
| `durationDays` | number | Длина текущего этапа (30; позже можно 180) |
| `longTermEndDate` | `YYYY-MM-DD` | Конец 6-месячной цели |
| `timezone` | string | `Asia/Almaty` (справочно) |
| `asOf` | `YYYY-MM-DD` (необяз.) | «Сегодня» для дашборда. **Если не указан — берётся текущая дата по Алматы (UTC+5).** В реальных данных не указывать |
| `lastUpdated` | ISO-время | Показывается в футере |

### profile
```json
{ "age": 23, "heightCm": 186 }
```
Справочно (рост/возраст использованы для расчёта калорий по Миффлину — Сан Жеору).

### targets
```json
{ "calories": 2000, "maintenanceCalories": 2890,
  "protein": null, "fat": null, "carbs": null,
  "workHoursPerDay": null, "workHoursPerWeek": null,
  "startWeight": 105, "goalWeight": 98.5, "goalWeightDate": "2026-10-28", "goalLabel": "−6–7 кг" }
```
- **Любую цель можно оставить `null`** — сайт покажет «цель не задана» вместо числа/полосы.
- `calories` — дневная цель; `maintenanceCalories` — поддержание (показывается подсказкой).
- `goalWeight` — число для расчётов (прогресс, план на графике); `goalLabel` — как показывать цель текстом
  (например «−6–7 кг»); `goalWeightDate` — срок (счётчик дней и нужный темп кг/нед).

### habits
```json
[
  { "id": "morning", "name": "Зарядка утром", "emoji": "🤸", "note": "минимум 10 минут, 1 раз в день" },
  { "id": "active4x10", "name": "Активность 4×10 мин", "emoji": "🚶", "target": 4, "note": "10 минут активности, 4 раза в день" }
]
```
`id` используется как ключ в `days[date].habits`. `note` — необязательная подпись.
- Без `target` — обычная привычка: в дне `true`/`false`.
- С `target` — **счётная** привычка: в дне число `0..target` (например `"active4x10": 3`);
  выполнена, когда значение ≥ `target`, частичное выполнение показывается заливкой ячейки.

### exercises
Сейчас пустой список `[]` (вкладка «Спорт» показывает пустое состояние). Формат на будущее:
```json
[{ "id": "bench", "name": "Жим лёжа", "metric": "weight", "unit": "кг" }]
```
`metric` — что считать лучшим результатом подхода: `weight` (макс. вес), `reps` (макс. повторы),
`distance` (макс. `distanceKm`), `time` (макс. `timeMin`).

### goals
Сейчас: одна цель месяца (вес, `auto: "weight"`), `sixMonth: []`. Формат:
```json
{ "id": "m-bench", "title": "Жим 80 кг на 5", "category": "Спорт",
  "start": 70, "current": 85, "target": 80, "unit": "кг" }
```
- Прогресс = `(current − start) / (target − start)`, поэтому цели «на снижение» (вес) работают сами.
- `category`: `Спорт` | `Работа` | `Развитие` | `Финансы` (цвет полосы; любая другая — серая).
- `auto` (необязательно) — считать `current` автоматически из дней:
  `"workHours"` (сумма часов работы за арку), `"workouts"` (число тренировок), `"weight"` (последний вес).
  Для остальных целей `current` обновляется вручную.
- `deadline` (необязательно, `YYYY-MM-DD`) — срок цели: показывается «срок … · осталось N дн.».

## Ежедневная запись `days["YYYY-MM-DD"]`

Все поля необязательны — можно добавлять только то, что известно.

```json
"2026-09-28": {
  "weight": 82.3,
  "tasks": [
    { "title": "Созвон с командой", "done": true },
    { "title": "Прочитать главу книги", "done": false }
  ],
  "habits": { "morning": true, "active4x10": 3 },
  "work": {
    "hours": 6.5,
    "notes": "Закрыл 3 задачи по проекту",
    "results": ["Задача #100", "Ревью PR"]
  },
  "workout": {
    "type": "Силовая — верх",
    "durationMin": 65,
    "notes": "Хорошее самочувствие",
    "exercises": [
      { "id": "bench",   "sets": [{ "weight": 72.5, "reps": 5 }, { "weight": 72.5, "reps": 5 }] },
      { "id": "pullups", "sets": [{ "weight": 0, "reps": 9 }] },
      { "id": "run",     "sets": [{ "distanceKm": 4.2, "timeMin": 27 }] }
    ]
  },
  "nutrition": {
    "meals": [
      { "type": "Завтрак", "name": "Овсянка с бананом", "kcal": 520, "protein": 18, "fat": 16, "carbs": 78 }
    ]
  },
  "note": "Свободная заметка дня"
}
```

- `workout: null` или отсутствие поля — день без тренировки.
- Итоги калорий/БЖУ за день считаются суммой `meals` (отдельно итог хранить не нужно).
- Привычка, отсутствующая в `habits` дня, считается невыполненной.
- Пустые разделы (нет задач/питания/работы/тренировок) — нормально: на сайте аккуратные пустые состояния.
- Недели считаются блоками по 7 дней от `startDate` (Неделя 1 = дни 1–7).

## Как добавить новый день (для ассистента)
1. Открыть `public/data/data.json`.
2. Добавить в `days` ключ с датой (`"2026-10-01": {...}`) по шаблону выше (порядок ключей не важен).
3. Обновить `meta.lastUpdated`, при необходимости `goals.*.current`.
4. Проверить валидность: `node -e "JSON.parse(require('fs').readFileSync('public/data/data.json','utf8'))"`.
5. `npm run build` (или просто скопировать JSON в `dist/data/`).


### finance
Курс и валюта показа. Дневные суммы на сайте всегда в USD.
```json
"finance": {
  "displayCurrency": "USD",
  "fx": {
    "pair": "USD/KZT",
    "kztPerUsd": 440.86,
    "date": "2026-10-01",
    "source": "Официальный курс Национального банка Республики Казахстан",
    "sourceUrl": "https://almaty.tv/ru/news/kurs-valyut/kurs-valut-na-1-oktabra-2026-goda"
  }
}
```
`kztPerUsd` — сколько тенге за 1 доллар на дату `date`. Цель месяца хранится в тенге (`goals.month` с `auto: "financeUsd"` и `targetKzt`), на экране делится на этот курс. Курс не выдумывается в интерфейсе.

### taskList
Список задач месяца (вкладка «Задачи»), не ежедневный чек-лист и не цели.
```json
"taskList": {
  "month": "2026-10",
  "label": "Задачи на октябрь",
  "items": [{ "id": "macbook", "title": "Купить MacBook Pro", "done": false, "date": null }]
}
```
`done: false` — задача открыта. `date` — день, к которому её привязали (`YYYY-MM-DD`), или `null`, если даты ещё нет. Не ставить дату, пока её не назвали.

## Дневной результат `pnlKzt`
В `days["YYYY-MM-DD"]` необязательное поле `pnlKzt` — число, которое назвали за день: плюс прибыль, минус убыток, в тенге. На календаре «Финансы» оно показывается в долларах по курсу `finance.fx`. Если поля нет — день пустой, ноль не подставляется.

Отметки привычек с телефона пишутся в `localStorage` браузера (ключ `winter-arc-habit-taps`), без сервера.
За сегодня они накладываются на `days[дата].habits`: нажатый ключ побеждает файл, остальные ключи берутся из JSON.
Счётная привычка `active4x10` по нажатию идёт по кругу 0→1→2→3→4→0.

## Расходы `expenses`

Траты в тенге. Они не входят в цель $1,2 млн и не пишутся в календарь `pnlUsd`.

На телефоне список хранится в `localStorage` (ключ `winter-arc-expenses`): массив `{id, date, amountKzt, note, category}`.
Категории: `Еда`, `Транспорт`, `Жильё`, `Одежда`, `Здоровье`, `Развлечения`, `Работа`, `Депозит`, `Другое`.
`Депозит` — отложенные деньги, не трата: в итоги недели, месяца и года и в круг по категориям не входит.

Позже те же суммы можно добавить в день (сайт сам файл не меняет):

```json
"expenses": [{ "id": "exp-1", "amountKzt": 2500, "note": "кофе", "category": "Еда" }]
```

`date` внутри элемента необязательна — берётся ключ дня. Если `id` совпал с записью на телефоне, на графиках побеждает телефон.
